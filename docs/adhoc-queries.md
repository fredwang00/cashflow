# Ad hoc queries

How to answer one-off questions ("were we charged for September?", "how much did we spend at Costco last year?") directly against the SQLite database, without writing new code.

## Opening the database

The database lives outside the repo at `~/.cashflow/cashflow.db` (override with `cashflow --db PATH`).

```bash
sqlite3 ~/.cashflow/cashflow.db          # interactive shell
sqlite3 ~/.cashflow/cashflow.db ".tables"
sqlite3 -header -column ~/.cashflow/cashflow.db "SELECT ..."
```

Read-only by default is safest: `sqlite3 "file:$HOME/.cashflow/cashflow.db?mode=ro"` (URI filenames need `.open` or the `-readonly` flag: `sqlite3 -readonly ~/.cashflow/cashflow.db`).

Python equivalent, used by the CLI and dashboard:

```python
import os, sqlite3
conn = sqlite3.connect(os.path.expanduser("~/.cashflow/cashflow.db"))
conn.row_factory = sqlite3.Row
```

## Schema cheat sheet

Full DDL is in `src/cashflow/db.py`. The tables that matter for queries:

| Table | Purpose |
|-------|---------|
| `transactions` | Charges, refunds, reimbursement offsets. One row per bank line item. |
| `amazon_items` | Amazon order items, optionally linked to a transaction via `transaction_id`. |
| `income` | Paycheck deposits (separate table, not negative transactions). |
| `categories` | `parent_id` hierarchy; `type` is `necessity` or `want`. |
| `accounts` | One bucket per export flavor (e.g. all BofA cards share one). |
| `merchant_rules` | `pattern` → `category_id`, source `manual` or `learned`. |
| `goals` | `ceiling` (monthly) and `surplus` (yearly) targets. |

### `transactions` column semantics

- **Amounts are signed**: charges are **positive**, refunds/credits are **negative**. There is no separate type column.
- **`canonical_id`** — set when a row is a duplicate/superseded copy of the transaction it points at. Always filter `WHERE canonical_id IS NULL` or you double-count.
- **`is_reimbursed` / `reimbursed_amount`** — the effective cost is `amount - reimbursed_amount` (e.g. a $400 charge with a $400 employer reimbursement costs $0).
- **`is_one_off` / `one_off_label`** — baseline vs one-off split used by the dashboard trend chart.
- **`status`** — `pending` (needs review) or `confirmed`.
- **`who`** — `fred`, `wife`, or `shared`.
- **Dates** are ISO strings; use `strftime('%Y', date)` / `strftime('%m', date)`, or plain string comparison `date >= '2026-09-01'`.

### The savings exclusion

Spending numbers deliberately exclude money moved into savings/investments. The canonical condition is generated by `not_savings()` in `src/cashflow/queries.py` (currently `Crypto/Investments`, `Investments`, `College Savings`, plus uncategorized transactions which always count). Mirror it in ad hoc SQL:

```sql
(t.category_id IS NULL OR t.category_id NOT IN
  (SELECT id FROM categories WHERE name IN ('Crypto/Investments','Investments','College Savings')))
```

If you skip it, your totals will be higher than `cashflow status` and the dashboard.

## Copy-paste recipes

### Spending by merchant, most recent month with data

```sql
SELECT merchant, ROUND(SUM(amount - reimbursed_amount), 2) AS total, COUNT(*) AS n
FROM transactions
WHERE canonical_id IS NULL
  AND (category_id IS NULL OR category_id NOT IN
       (SELECT id FROM categories WHERE name IN ('Crypto/Investments','Investments','College Savings')))
  AND amount > 0
GROUP BY merchant ORDER BY total DESC LIMIT 25;
```

### Monthly spend in one category (trend across the year)

```sql
SELECT strftime('%Y-%m', date) AS month, ROUND(SUM(amount - reimbursed_amount), 2) AS total
FROM transactions
WHERE canonical_id IS NULL
  AND category_id = (SELECT id FROM categories WHERE name = 'Groceries')
GROUP BY month ORDER BY month;
```

### Find every charge from a merchant (e.g. "were we charged in Aug/Sept?")

```sql
SELECT t.date, t.amount, t.merchant, t.description, a.name AS account, c.name AS category
FROM transactions t
JOIN accounts a ON t.account_id = a.id
LEFT JOIN categories c ON t.category_id = c.id
WHERE LOWER(t.merchant) LIKE '%wendy-suspect-merchant%'   -- substring, case-insensitive
  AND t.canonical_id IS NULL
ORDER BY t.date;
```

Tip: if the exact merchant string is unknown, find it first with
`SELECT DISTINCT merchant FROM transactions WHERE LOWER(description) LIKE '%keyword%';`

### Recurring charges of the same amount (subscription audit)

```sql
SELECT merchant, amount, COUNT(*) AS times,
       MIN(date) AS first_seen, MAX(date) AS last_seen,
       GROUP_CONCAT(DISTINCT strftime('%Y-%m', date)) AS months
FROM transactions
WHERE canonical_id IS NULL AND amount > 0
GROUP BY merchant, amount
HAVING COUNT(*) >= 3
ORDER BY last_seen DESC;
```

### Per-person spending

```sql
SELECT who, ROUND(SUM(amount - reimbursed_amount), 2) AS total
FROM transactions
WHERE canonical_id IS NULL AND strftime('%Y', date) = '2026'
GROUP BY who;
```

### Burn rate exactly as `cashflow status` computes it

```sql
-- month spending
SELECT ROUND(COALESCE(SUM(amount - reimbursed_amount), 0), 2)
FROM transactions
WHERE canonical_id IS NULL
  AND (category_id IS NULL OR category_id NOT IN
       (SELECT id FROM categories WHERE name IN ('Crypto/Investments','Investments','College Savings')))
  AND strftime('%Y-%m', date) = '2026-09';

-- month income
SELECT ROUND(COALESCE(SUM(amount), 0), 2) FROM income WHERE strftime('%Y-%m', date) = '2026-09';
```

`src/cashflow/queries.py` is the source of truth for these formulas.

### Amazon items linked to a transaction

```sql
SELECT t.date, t.merchant, t.amount, i.order_number, i.item_name, i.price, i.account
FROM amazon_items i
LEFT JOIN transactions t ON i.transaction_id = t.id
WHERE t.date >= '2026-01-01'
ORDER BY t.date DESC;
```

Unresolved orders have `transaction_id IS NULL`.

### Review queue depth

```sql
SELECT COUNT(*) FROM transactions WHERE canonical_id IS NULL AND status = 'pending';
```

## Gotchas

- **Deduplication is by `source_id`**, not by amount/date/merchant. Re-ingesting the same export is safe; two genuinely identical same-day purchases may both exist (Chase/Robinhood add occurrence suffixes). Reconcile against statement totals before deleting anything.
- **Refunds are negative rows**, not an `is_refund` flag. Net-of-refund totals come from summing signed amounts; "spending" reports filter `amount > 0` or rely on the sign netting out.
- **Income is not in `transactions`** — it's a separate table filled only by the BofA checking paycheck pattern. Other deposits won't appear in surplus math.
- **`accounts` are buckets**, not physical cards (all BofA cards share one), so account freshness can't prove each card is current.
- Write nothing by hand unless you understand the dedup/snapshot rules in [data-preservation.md](data-preservation.md); prefer the CLI (`cashflow tag`, `cashflow recategorize`, `cashflow rule set`) for mutations.
